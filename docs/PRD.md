## 1. 프로젝트 개요

### 1.1 목적

Notion을 CMS(Content Management System)로 활용하는 개인 기술 블로그를 구축한다. 작성자는 익숙한 Notion 편집 환경에서 글을 쓰고, 상태를 `발행됨`으로 바꾸기만 하면 별도의 배포 작업 없이 블로그에 자동으로 반영된다.

### 1.2 CMS로 Notion을 선택한 이유

- **작성 경험**: 별도의 관리자 페이지를 만들 필요 없이 Notion의 풍부한 에디터(코드 블록, 이미지, 표, 콜아웃 등)를 그대로 사용한다.
- **자동 반영**: Notion 데이터베이스의 상태 값만으로 발행 여부를 제어하고, 블로그는 주기적 재검증으로 최신 내용을 가져온다.
- **비용 및 운영 부담 최소화**: 별도 DB·백엔드 서버 없이 Notion API와 Vercel만으로 운영한다.
- **모바일 작성**: Notion 모바일 앱에서도 글 작성·수정이 가능하다.

### 1.3 대상 사용자

| 사용자       | 설명                     | 주요 니즈                                               |
| ------------ | ------------------------ | ------------------------------------------------------- |
| 작성자(본인) | 블로그 운영자            | Notion에서 쓰면 바로 반영되는 간편한 발행 흐름          |
| 독자         | 개발자, 기술 정보 탐색자 | 빠른 로딩, 읽기 편한 본문, 카테고리·검색을 통한 글 탐색 |

### 1.4 성공 지표

- Notion에서 `발행됨`으로 변경한 글이 재검증 주기(기본 1시간) 이내에 블로그에 반영된다.
- Lighthouse 성능·접근성·SEO 점수 각 90점 이상
- 모바일(360px)부터 데스크톱(1440px)까지 레이아웃 깨짐 없음

| 구분        | 기술                                                     | 비고                           |
| ----------- | -------------------------------------------------------- | ------------------------------ |
| Framework   | Next.js 16 (App Router), TypeScript                      | `next@16.3.6`, React 19.2      |
| CMS         | Notion API (`@notionhq/client`)                          | 서버 컴포넌트에서만 호출       |
| 본문 렌더링 | `notion-to-md` + Markdown 렌더러 (또는 블록 직접 렌더링) | 구현 단계에서 확정             |
| Styling     | Tailwind CSS v4, shadcn/ui                               | 기존 프로젝트 설정 활용        |
| Icons       | Lucide React                                             |                                |
| Theme       | next-themes                                              | 다크 모드 지원(기존 설정 활용) |
| Deployment  | Vercel                                                   |                                |

> **버전 결정**: 초기 요구사항의 Next.js 15 대신, 프로젝트에 설치된 `next@16.3.6`을 유지한다. 구현 시 `AGENTS.md` 지침에 따라 `node_modules/next/dist/docs/`의 가이드를 먼저 확인하고, 학습 데이터나 이전 버전 자료가 아닌 설치된 버전의 문서를 기준으로 한다.

### 2.1 Next.js 16 구현 지침

| 항목                   | 지침                                                                                                                                                                                                                                                        |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 동적 라우트 `params`   | `params`, `searchParams`는 Promise이므로 `const { slug } = await params` 형태로 사용한다. `generateMetadata`도 동일하다                                                                                                                                     |
| 페이지 Props 타입      | 가능하면 `next typegen`이 생성하는 `PageProps<'/posts/[slug]'>` 전역 타입을 사용한다 (`npm run typecheck`에 포함)                                                                                                                                           |
| 캐싱·재검증 (MVP)      | `cacheComponents`를 켜지 않은 현재 설정을 유지하고, 페이지에 `export const revalidate = 3600` 세그먼트 설정 + `generateStaticParams`로 ISR을 구성한다                                                                                                       |
| 캐싱·재검증 (Post-MVP) | 즉시 반영이 필요하면 `next.config.ts`에 `cacheComponents: true`를 켜고, Notion 조회 함수를 `'use cache'` + `cacheLife()` + `cacheTag('posts')`로 감싼 뒤 Route Handler에서 태그 단위로 무효화한다. 이때 세그먼트 `revalidate` 설정은 `cacheLife`로 대체한다 |
| 클라이언트 검색        | `useSearchParams`를 쓰는 검색 컴포넌트는 `<Suspense>`로 감싸 정적 렌더링이 깨지지 않도록 한다                                                                                                                                                               |
| 번들러                 | `next dev`·`next build`는 Turbopack이 기본이다. 별도 webpack 설정을 추가하지 않는다                                                                                                                                                                         |
| 요청 가로채기          | 필요 시 `middleware.ts` 대신 `proxy.ts` 규칙을 따른다 (MVP에서는 사용하지 않음)                                                                                                                                                                             |

> 위 항목은 구현 직전에 설치된 버전 문서로 다시 확인한다. 특히 `revalidateTag`/`updateTag`의 시그니처는 버전에 따라 달라질 수 있다.

## 3. Notion 데이터베이스 구조

### 3.1 속성 정의

| 속성명    | 타입           | 필수 | 설명                                              |
| --------- | -------------- | ---- | ------------------------------------------------- |
| Title     | `title`        | ✅   | 글 제목                                           |
| Category  | `select`       | ✅   | 글 카테고리 (예: Frontend, Backend, DevOps, 회고) |
| Tags      | `multi_select` |      | 글 태그 (예: React, Next.js, TypeScript)          |
| Published | `date`         | ✅   | 발행일 (목록 정렬 기준)                           |
| Status    | `select`       | ✅   | `초안` / `발행됨`                                 |
| Content   | page content   | ✅   | 페이지 본문 블록 (속성이 아닌 페이지 내부 콘텐츠) |

### 3.2 추가 권장 속성 (선택)

MVP 필수는 아니지만 URL과 목록 품질을 위해 추가를 권장한다.

| 속성명      | 타입        | 설명                                                          |
| ----------- | ----------- | ------------------------------------------------------------- |
| Slug        | `rich_text` | 글 URL 경로 (예: `nextjs-notion-blog`). 없으면 페이지 ID 사용 |
| Description | `rich_text` | 목록 카드 및 SEO 메타 설명용 요약                             |

### 3.3 데이터 조회 규칙

- `Status = 발행됨`인 글만 조회한다. `초안`은 어떤 경로로도 노출되지 않아야 한다.
- 목록은 `Published` 내림차순으로 정렬한다.
- Notion API는 한 번에 최대 100건을 반환하므로 `has_more` / `next_cursor`로 페이지네이션 처리한다.

### 3.4 TypeScript 데이터 모델

```ts
// 블로그 글 목록/상세에서 공통으로 사용하는 글 메타데이터
export interface Post {
  id: string;
  slug: string;
  title: string;
  category: string;
  tags: string[];
  publishedAt: string; // ISO 8601 날짜 문자열
  description?: string;
}

// 상세 페이지용: 메타데이터 + 본문
export interface PostDetail extends Post {
  content: string; // 변환된 Markdown 또는 렌더링용 블록 데이터
}
```

## 4. 주요 기능 요구사항

### F1. Notion 데이터베이스에서 글 목록 가져오기 (MVP)

- 서버에서 Notion API로 발행된 글 목록을 조회한다.
- 각 글은 제목, 카테고리, 태그, 발행일, 요약을 카드 형태로 표시한다.
- 데이터는 정적 생성 + 주기적 재검증(ISR)으로 캐싱하여 Notion API 호출을 최소화한다.
- **완료 조건**: Notion에서 `발행됨` 상태의 글만 최신순으로 표시된다.

### F2. 개별 글 상세 페이지 (MVP)

- `/posts/[slug]` 경로에서 글 메타데이터와 본문을 표시한다.
- 지원해야 할 Notion 블록: 문단, 제목(H1~H3), 목록(순서/비순서), 코드 블록(구문 강조), 인용, 콜아웃, 이미지, 구분선, 링크, 표.
- 존재하지 않거나 `초안` 상태인 글 접근 시 404 페이지를 표시한다.
- 페이지별 메타데이터(title, description, Open Graph)를 생성한다.
- **완료 조건**: Notion 본문이 서식을 유지한 채 읽기 좋은 타이포그래피로 렌더링된다.

### F3. 카테고리별 필터링

- `/category/[category]` 경로에서 해당 카테고리 글만 표시한다.
- 홈 및 카테고리 페이지에 카테고리 목록(글 개수 포함)을 탭 또는 배지 형태로 제공한다.
- **완료 조건**: 카테고리 선택 시 해당 카테고리의 발행된 글만 표시된다.

### F4. 검색 기능

- 제목, 요약, 태그를 대상으로 키워드 검색을 제공한다.
- 글 수가 많지 않은 개인 블로그 특성상, 빌드/재검증 시 생성한 글 목록을 기반으로 클라이언트 측 필터링을 우선 적용한다(Notion API 호출 없음).
- 검색어는 URL 쿼리(`?q=`)로 유지하여 공유·뒤로 가기가 가능하도록 한다.
- **완료 조건**: 검색어 입력 시 일치하는 글만 표시되고, 결과가 없으면 안내 문구를 표시한다.

### F5. 반응형 디자인 (MVP)

- 모바일(< 640px), 태블릿(640~1024px), 데스크톱(> 1024px) 브레이크포인트를 지원한다.
- 모바일에서는 기존 `mobile-nav` 컴포넌트(Sheet)를 활용한 내비게이션을 제공한다.
- 본문 가독성을 위해 최대 너비(약 `65ch~768px`)를 제한한다.
- 다크 모드를 지원한다(기존 `theme-toggle` 활용).

## 5. 화면 구성

### 5.1 라우트 구조

| 경로                   | 화면                        | 렌더링 방식                                | MVP |
| ---------------------- | --------------------------- | ------------------------------------------ | --- |
| `/`                    | 홈 – 최근 글 목록           | 정적 생성 + 재검증                         | ✅  |
| `/posts/[slug]`        | 글 상세                     | 정적 생성(`generateStaticParams`) + 재검증 | ✅  |
| `/category/[category]` | 카테고리별 글 목록          | 정적 생성 + 재검증                         |     |
| `/search?q=`           | 검색 결과 (또는 홈 내 검색) | 클라이언트 필터링                          |     |

### 5.2 화면별 구성 요소

**홈 (`/`)**

```
┌──────────────────────────────────────┐
│ Header: 로고 | 카테고리 | 검색 | 테마  │
├──────────────────────────────────────┤
│ 소개 문구 (Hero)                      │
│ [전체] [Frontend] [Backend] [회고]    │ ← 카테고리 필터
│ ┌──────────┐ ┌──────────┐            │
│ │ 글 카드   │ │ 글 카드   │  ...       │ ← 모바일 1열 / 데스크톱 2~3열
│ └──────────┘ └──────────┘            │
├──────────────────────────────────────┤
│ Footer                               │
└──────────────────────────────────────┘
```

- 글 카드: 카테고리 배지, 제목, 요약, 태그, 발행일

**글 상세 (`/posts/[slug]`)**

- 상단: 카테고리 배지, 제목, 발행일, 태그
- 본문: Notion 블록 렌더링 영역
- 하단: 목록으로 돌아가기 링크 (선택: 이전/다음 글)

**카테고리 (`/category/[category]`)**

- 카테고리명과 글 개수 표시
- 해당 카테고리 글 카드 목록 (홈과 동일한 카드 컴포넌트 재사용)

### 5.3 활용할 shadcn/ui 컴포넌트

기존 프로젝트에 설치된 컴포넌트를 우선 활용한다.

| 컴포넌트    | 용도              |
| ----------- | ----------------- |
| `Card`      | 글 목록 카드      |
| `Badge`     | 카테고리, 태그    |
| `Input`     | 검색창            |
| `Tabs`      | 카테고리 필터     |
| `Separator` | 본문 구분         |
| `Sheet`     | 모바일 내비게이션 |
| `Button`    | 공통 버튼         |

## 6. 시스템 아키텍처

### 6.1 데이터 흐름

```
[작성자] ──작성/발행──▶ [Notion DB]
                            │
                            │ Notion API (서버에서만 호출)
                            ▼
                 [Next.js 서버 컴포넌트]
                   (정적 생성 + 재검증 캐시)
                            │
                            ▼
                     [Vercel CDN] ──▶ [독자]
```

### 6.2 디렉토리 구조 (안)

```
src/
├── app/
│   ├── page.tsx                    # 홈: 최근 글 목록
│   ├── posts/[slug]/page.tsx       # 글 상세
│   └── category/[category]/page.tsx # 카테고리별 목록
├── components/
│   ├── blog/
│   │   ├── post-card.tsx           # 글 카드
│   │   ├── post-list.tsx           # 글 목록
│   │   ├── category-filter.tsx     # 카테고리 필터
│   │   ├── search-input.tsx        # 검색 입력 (클라이언트 컴포넌트)
│   │   └── post-content.tsx        # 본문 렌더러
│   ├── layout/                     # 기존 헤더/푸터/모바일 내비
│   └── ui/                         # 기존 shadcn/ui 컴포넌트
├── lib/
│   ├── notion.ts                   # Notion 클라이언트 및 조회 함수
│   └── utils.ts
└── types/
    └── post.ts                     # Post, PostDetail 타입
```

### 6.3 Notion 연동 모듈 (`src/lib/notion.ts`) 주요 함수

| 함수                           | 설명                                                 |
| ------------------------------ | ---------------------------------------------------- |
| `getPublishedPosts()`          | 발행된 전체 글 목록 조회 (페이지네이션 처리, 최신순) |
| `getPostBySlug(slug)`          | 슬러그로 글 메타데이터 + 본문 조회                   |
| `getPostsByCategory(category)` | 카테고리별 글 목록 조회                              |
| `getCategories()`              | 카테고리 목록과 글 개수 조회                         |

### 6.4 환경 변수

| 변수명               | 설명                         |
| -------------------- | ---------------------------- |
| `NOTION_API_KEY`     | Notion Integration 시크릿 키 |
| `NOTION_DATABASE_ID` | 블로그 글 데이터베이스 ID    |

- `.env.local`에 저장하고 Git에 커밋하지 않는다.
- `NEXT_PUBLIC_` 접두사를 사용하지 않아 클라이언트 번들에 노출되지 않도록 한다.
- Vercel 프로젝트 설정의 Environment Variables에도 동일하게 등록한다.

## 7. 비기능 요구사항

| 구분      | 요구사항                                                                                                                 |
| --------- | ------------------------------------------------------------------------------------------------------------------------ |
| 성능      | 정적 생성 + 재검증으로 페이지 응답을 CDN에서 제공. LCP 2.5초 이하                                                        |
| 이미지    | Notion 이미지 URL은 약 1시간 후 만료되므로, 재검증 주기를 만료 시간보다 짧게 유지하거나 이미지 프록시/외부 호스팅을 검토 |
| API 제한  | Notion API 요청 제한(평균 초당 3회)을 고려해 캐싱으로 호출 수를 최소화                                                   |
| 보안      | API 키는 서버에서만 사용. 초안 글은 어떤 경로로도 노출 금지                                                              |
| SEO       | 페이지별 메타데이터, Open Graph, `sitemap.xml`, `robots.txt` 생성                                                        |
| 접근성    | 시맨틱 HTML, 키보드 내비게이션, 충분한 색 대비(라이트/다크 모두)                                                         |
| 에러 처리 | Notion API 실패 시 기존 `error.tsx`로 안내, 없는 글은 `not-found.tsx` 표시                                               |

## 8. MVP 범위

### 8.1 포함 (In Scope)

- [ ] Notion API 연동 (`@notionhq/client`)
- [ ] 글 목록 페이지 (홈)
- [ ] 글 상세 페이지
- [ ] 기본 스타일링 (Tailwind CSS + shadcn/ui)
- [ ] 반응형 디자인

### 8.2 MVP 이후 (Post-MVP)

- 카테고리별 필터링 페이지
- 검색 기능
- 태그별 필터링
- 목차(TOC), 읽기 시간 표시
- 이전/다음 글 내비게이션
- 댓글(giscus 등), RSS 피드
- Notion 웹훅 또는 On-demand Revalidation을 통한 즉시 반영

### 8.3 제외 (Out of Scope)

- 블로그 내 관리자 페이지 및 글 작성 기능 (Notion에서만 작성)
- 회원가입/로그인
- 다국어 지원

## 9. 구현 단계

| 단계 | 작업                                    | 주요 산출물                                                                  | 완료 조건                                |
| ---- | --------------------------------------- | ---------------------------------------------------------------------------- | ---------------------------------------- |
| 1    | Notion API 패키지 설치 및 환경 설정     | `@notionhq/client` 설치, `.env.local`, `src/lib/notion.ts` 기본 클라이언트   | 서버에서 Notion 클라이언트 초기화 성공   |
| 2    | Notion 데이터베이스 생성 및 API 키 설정 | Notion DB(3장 구조), Integration 생성 및 DB 연결, 샘플 글 3건 이상           | API로 샘플 글 조회 성공                  |
| 3    | 글 목록 페이지 구현                     | `getPublishedPosts()`, `PostCard`, `PostList`, 홈 페이지                     | 발행된 글만 최신순 표시                  |
| 4    | 글 상세 페이지 구현                     | `getPostBySlug()`, 본문 렌더러, `/posts/[slug]`, 메타데이터                  | 본문이 서식 유지하여 렌더링, 없는 글 404 |
| 5    | 스타일링 및 최적화                      | 반응형 레이아웃, 다크 모드, 본문 타이포그래피, 재검증 설정, SEO, Vercel 배포 | Lighthouse 각 항목 90점 이상, 배포 완료  |

### 9.1 단계별 세부 작업

**1단계: 패키지 설치 및 환경 설정**

```bash
npm install @notionhq/client notion-to-md
```

- `.env.local`에 `NOTION_API_KEY`, `NOTION_DATABASE_ID` 추가
- `.gitignore`에 `.env*.local` 포함 여부 확인

**2단계: Notion 데이터베이스 및 Integration 설정**

1. [Notion Integrations](https://www.notion.so/my-integrations)에서 Internal Integration 생성 (읽기 권한)
2. 3장 구조로 데이터베이스 생성
3. 데이터베이스 페이지의 `연결(Connections)` 메뉴에서 Integration 추가
4. 데이터베이스 URL에서 ID 추출하여 환경 변수에 등록

**3단계: 글 목록 페이지**

- Notion 응답 객체를 `Post` 타입으로 변환하는 매퍼 작성
- `Status = 발행됨` 필터 + `Published` 내림차순 정렬 쿼리 작성
- 홈 페이지를 서버 컴포넌트로 구현하고 재검증 주기 설정

**4단계: 글 상세 페이지**

- `generateStaticParams`로 발행된 글의 슬러그 사전 생성
- 페이지 블록 조회(하위 블록 재귀 처리 포함) 후 본문 렌더링
- `generateMetadata`로 페이지별 SEO 메타데이터 생성

**5단계: 스타일링 및 최적화**

- 본문 타이포그래피 스타일 적용 (코드 블록 구문 강조 포함)
- 브레이크포인트별 레이아웃 점검
- `sitemap.ts`, `robots.ts` 추가
- 린트·타입 체크 통과 후 Vercel 배포 및 환경 변수 등록
